# Student Planner 文档边界整理设计

## 目标

让新 session 能在几分钟内确认协作规则、当前状态、开放问题和长期架构，同时保留必要历史证据，但不让历史流水继续挤占主入口。

## 文件职责

- `AGENTS.md`：协作规则、阅读顺序和稳定的优先领域；具体当前状态统一引用 `progress.md`，不维护第二份进度。
- `context.md`：长期稳定的产品定位、运行时边界、仓库地图和文档索引。
- `progress.md`：当前阶段、最近完成、验证基线、工作区状态、下一步和活跃风险。
- `bugs.md`：仍开放的问题、长期环境约束、延期项和禁止重复的失败路径。
- `docs/archive/progress-through-2026-07-11.md`：整理前 `progress.md` 的完整快照。
- `docs/archive/bugs-through-2026-07-11.md`：整理前 `bugs.md` 的完整快照。
- `docs/superpowers/specs/`：设计意图和稳定契约。
- `docs/superpowers/plans/`：执行清单；完成后标记状态并冻结。

## 整理规则

1. 主入口使用主题和状态组织，不再按日期持续追加流水。
2. 整理前先把两个源文件逐字节复制为固定命名的归档快照，再改写主入口；压缩只发生在主入口，归档不做删改。
3. `progress.md` 只保留最近一至两个 session 的结果；其余内容通过完整快照保留。
4. `bugs.md` 只保留仍会影响开发、验证或部署的条目；已修复历史通过完整快照保留。
5. 长期有效的 Windows、测试、Chroma、部署与 Web Push 环境约束继续保留，但主入口只保留结论和处置方式，不重复案例流水。
6. 不修改业务代码、测试、数据库、RAG 语料或现有功能设计。
7. 不批量修改既有 spec 或 plan；“完成后冻结”只是后续维护规则，不属于本轮整理范围。
8. 不清理或覆盖工作区中已有的未提交功能变更。

## 脏工作区保护

1. 修改前保存 `git status --short`、`git diff --name-status`、四个入口文件的 SHA-256，以及所有非目标脏文件（包含未跟踪文件和二进制文件）的逐文件 SHA-256。
2. 因 `progress.md` 已有未提交改动，归档快照必须取当前工作区内容，而不是 `HEAD` 内容。
3. 整理后确认所有非目标路径的状态、修改类型和逐文件 SHA-256 均与修改前一致；本轮目标路径仅限四个入口文件、两个归档快照和本设计说明。
4. 使用归档快照的 SHA-256 与修改前源文件 SHA-256 对比，证明归档未丢字节。

## 目标结构

### `progress.md`

1. 当前阶段
2. 最近完成
3. 当前验证基线
4. Git / 工作区状态
5. 下一步
6. 活跃风险

### `bugs.md`

1. 开放问题
2. 环境约束
3. 延期项
4. 不要重复的失败路径
5. 历史归档链接，统一使用仓库相对链接

每个开放问题统一包含状态、优先级、影响、证据和下一步。

## 验证

- 四个入口文件职责互不重叠，且能独立说明各自范围。
- `progress.md` 和 `bugs.md` 明显缩短；两个归档文件的 SHA-256 分别等于整理前两个源文件的 SHA-256。
- `progress.md`、`bugs.md` 与 `context.md` 都使用仓库相对链接指向固定归档文件。
- 只检查本轮新增或改写的 Markdown 相对链接；目标必须存在。既有全仓绝对链接不作为本轮阻塞项。
- `git diff --check` 通过。
- 非目标路径的 `git status --short`、`git diff --name-status` 和逐文件 SHA-256 与修改前基线一致。
